# 要求

`docs/devel/requirements/`

実現すべき要求・制約・前提を管理する。設計や実装方法ではなく「なぜ必要か」
「何が求められているか」を記述する。

## 配置するもの

- 業務要求 / 機能要求 / 非機能要求
- 技術制約 / 運用制約 / 移行制約
- 契約・環境上の前提
- 利用者・関係者
- スコープ / スコープ外

## 隣接カテゴリとの境界

- 何を満たせば正しいか（振る舞い・I/F・業務ルール） → `../specs/`
- どう実現するか（構造・責務・処理方式） → `../design/`

## 規模が小さい場合

`requirements.md` 単一ファイルで運用してよい。
