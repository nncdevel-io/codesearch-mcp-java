# 仕様

`docs/devel/specs/`

満たすべき振る舞い・入出力・業務ルールを管理する。設計方法ではなく「何を満たせば
正しいか」を記述する。

外部公開I/F、または複数チーム連携を持つプロジェクトでは必須。内部完結のライブラリ・
CLI・PoC では任意。

## 配置するもの

- API仕様 / 画面仕様 / バッチ仕様
- 外部インタフェース仕様 / ファイル連携仕様
- 業務ルール / バリデーション条件 / エラー仕様
- 正常系・異常系の振る舞い

## 隣接カテゴリとの境界

- なぜ必要か → `../requirements/`
- どう実現するか → `../design/`

## 規模が小さい場合

`specs.md` 単一ファイルで運用してよい。
