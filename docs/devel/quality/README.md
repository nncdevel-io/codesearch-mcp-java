# 品質

`docs/devel/quality/`

**品質基準・レビュー観点・完了条件**を管理する。

`testing/` が「どう検証するか」を扱うのに対し、`quality/` は「何を満たせば十分か」
を扱う。

## 配置するもの

- レビュー観点（恒久的なもの）
- Definition of Done
- 品質ゲート
- 静的解析基準
- 複雑度・重複・可読性の基準
- セキュリティ・パフォーマンス確認観点
- リリース前チェック観点

## 隣接カテゴリとの境界

- どう検証するか（テスト方法・実行） → `../testing/`
- 一時的なレビュー結果・指摘一覧 → `../work/reviews/`
- 実装規約 → `../standards/`

## 規模が小さい場合

`quality.md` 単一ファイルで運用してよい。
