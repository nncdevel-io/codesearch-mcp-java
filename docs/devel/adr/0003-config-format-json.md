# ADR-0003: 設定ファイル形式に JSON（Jackson）を採用する

## ステータス

Accepted（2026-06-29）

## 背景

設定ファイル（`repos`／`secrets`／`server`）の形式を選定する。当初は Python 版
との「設定互換」を理由に TOML を選んでいたが、設定互換は本プロジェクトの目標
ではないと確認された（要件 §5.7 で互換は非目標と明記）。したがって判断軸は
**追加依存の少なさ**と**手編集のしやすさ**のみである。

設定は、トップレベルのスカラーに加え、リポジトリの**オブジェクト配列**、
`exclude_paths` 等の配列、id をキーにした `secrets` マップを含むネスト構造を持つ。

## 検討した選択肢

| 形式 | 追加依存 | ネスト・配列適合 | コメント | 手編集 | 結論 |
| --- | --- | --- | --- | --- | --- |
| A. JSON（Jackson） | **ゼロ**（Jackson は `rg --json` 解析・ツール出力で既に依存） | ◎ | ✗ | △ | **採用** |
| B. Properties（JDK 標準） | ゼロ | ✗（フラット。配列が添字キーになり煩雑） | ✓ | △ | 不採用 |
| C. TOML（tomlj） | +2（tomlj＋ANTLR） | ◎ | ✓ | ◎ | 不採用（依存増） |
| D. YAML（snakeyaml） | +1 | ◎ | ✓ | ◯ | 不採用（依存増） |

## 決定

**A. JSON を採用し、既存依存の Jackson でパースする。**

- 追加ライブラリーがゼロ。Jackson は ripgrep の `--json` 出力解析とツール出力
  整形のため core に既に存在する。
- ネスト・配列を自然に表現でき、リポジトリ配列・`secrets` マップ・`exclude_paths`
  をそのまま書ける（Properties はフラットで構造に合わず不採用）。
- コメント不可という JSON の弱点は、同梱の `*.json.example` と
  `docs/devel/specs/spec.md` §7 の記述で補う。

## 帰結

- core の設定ローダー（`ConfigLoader`）は Jackson の `ObjectMapper#readTree` で
  パースする。`tomlj`／ANTLR への依存は持たない。
- 設定ファイル名は `repos.json`／`secrets.json`／`server.json`。スキーマは
  spec §7 を参照。
- 利用者は設定にコメントを書けない（運用ドキュメントと example で補完する）。

## レビュー条件（この決定を再評価する契機）

- 運用者からの強い要望でコメント付き手編集が必須になった場合、TOML または
  YAML への移行を再検討する（その際は依存追加コストを受容する判断を記録する）。
