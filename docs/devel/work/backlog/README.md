# バックログ

`docs/devel/work/backlog/`

**未着手・未確定**の作業候補を整理する。要件から掘り起こした実装機能を、
レビューできる単位（feature）にまとめる段でもある。

Backlog / Jira / GitHub Issues 等のチケット管理システムを利用している場合、作業
管理の正本はチケット側に置く。本ディレクトリはリポジトリ内で作業候補を整理し、
開発者・コーディングエージェントが理解しやすい形に補助的にまとめる場所。

第二のチケット管理システムにしない。

## 配置するもの

- チケット化前の作業候補
- 技術的負債の棚卸し
- リファクタリング候補
- AIエージェントに渡す前の作業候補
- 複数チケットをまたぐ技術的作業分解
- 優先度・実施可否が未確定の改善案

## 流れ

要件を起点に `plans`（順序・フェーズ）→ `backlog`（機能へ分解）→ `tasks`（実行）
と流れる。backlog は機能の説明として残してよく、必ずしも移動・削除しない。

- 着手が決まった機能 → `../tasks/task.md` に分解して実行（backlog 側は残してよい）
- フェーズ・順序に束ねる → `../plans/`
- 要件が明確なら → backlog を飛ばして直接 `../tasks/` を作る
- 失効・不要 → `../archive/` へ移動または削除
