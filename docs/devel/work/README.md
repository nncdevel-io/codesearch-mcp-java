# 作業ドキュメント

`docs/devel/work/`

個別作業に紐づく**一時的または準一時的**な文書を管理する。

恒久的に参照する文書は本ディレクトリ配下ではなく、`../requirements/`、
`../design/`、`../adr/` 等の恒久文書側に配置する。

## サブカテゴリ

- `backlog/` — 未着手・未確定の作業候補
- `tasks/` — 実行が決まった作業指示（完了・中止タスクは `tasks/done/`）
- `plans/` — 複数作業を束ねる計画・対応方針
- `investigations/` — 調査・分析記録
- `reviews/` — 一時的なレビュー結果
- `notes/` — 暫定メモ
- `archive/` — 古くなった・失効した作業文書

## 作業の流れ（plan / backlog / task）

`plans/`・`backlog/`・`tasks/` は対立する選択肢でも入れ子でもなく、要件を起点と
した一本の流れの異なる段。各段は規模と要件の明確さに応じて省略してよい。

```text
要件
 ├─▶ plans/   : 要件の塊をどの順・どのフェーズで進めるか（順序づけ）
 ├─▶ backlog/ : 要件の塊を機能（レビューできる単位）に分解
 └─▶ tasks/   : 実行単位（backlog から分解、または明確な要件から直接）
```

- 大規模開発・初期構築 → `plans/` でフェーズに分ける
- 要件が大きい・曖昧 → `backlog/` で機能単位に分解
- 要件が明確・小規模 → `plans`/`backlog` を飛ばして `tasks/` を直接作る

同じ内容を重複させない。順序は `plans`、機能の中身は `backlog`、実行手順は
`tasks` と粒度で書き分け、他の段は参照でつなぐ。

## 恒久文書への昇格

`work/` で得た知見のうち、今後も参照すべき内容は該当する恒久文書へ反映する。

| 内容 | 反映先 |
| --- | --- |
| 要求に関する内容 | `../requirements/` |
| 仕様に関する内容 | `../specs/` |
| 現在の設計に関する内容 | `../design/` |
| 設計判断・技術選定 | `../adr/` |
| 実装規約 | `../standards/` |
| テスト方針 | `../testing/` |
| 品質基準 | `../quality/` |
| 運用手順 | `../operation/` |

タスクの完了・中止は `tasks/done/` へ。古くなった・失効した文書は `archive/`
へ移動するか削除する。
